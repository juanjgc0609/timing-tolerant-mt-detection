F1 [EXPL] Matched-filter kernel switched to 3 Hz without switching the deflation / Gram kernel, and inconsistently
    across C18h, C18i and C18j.
  Where: explore_contrib/c18h_kernel.py:20-23 (set_kernel rebinds task1o_consistent._KER only);
    task1x_mtglrt.py:57-59 (AC = ricker(2 Hz) correlated with _KER, computed ONCE at import time);
    task2c_methods.py:62-64 (AC, AC_HALF copied from X at import); c18i_widesc.py:15 and 29; c18j_layered.py:19 and 84
    (r0_run, hence task1x_mtglrt, imported BEFORE set_kernel).
  What: set_kernel changes the kernel used by matched() (readings, station terms, scores) but the deflation shape
    X.AC (used by c10_lib._deflate, task2d synth_sub, and M.ac_at in the BOMP Gram) is whatever existed when
    task1x_mtglrt was first imported. c18h_detect.py calls set_kernel before importing c18d_detect, so its AC is
    "2 Hz Ricker correlated with the 3 Hz kernel". c18i_widesc.py (detect, FC=3) and c18j_layered.py (FC=3) import
    r0_run first, so their AC stays "2 Hz wavelet x 2 Hz kernel" while the matched filter is 3 Hz.
  Reproduction (ac_order_bh.py -> ac_order_bh.txt; each import order in a fresh interpreter):
      c18h_detect order : AC(+-2) -0.303  AC(+-4) -0.352  AC(+-6) +0.114   (2 Hz wavelet x 3 Hz kernel)
      c18i / c18j FC=3  : AC(+-2) -0.079  AC(+-4) -0.555  AC(+-6) +0.011   (identical to the 2 Hz reference)
      response of a 3 Hz arrival to the 3 Hz kernel: a(+-1) 0.291, a(+-2) -0.566, a(+-4) +0.011
    So the three "3 Hz" detector runs deflate every accepted atom (kmax 6) with three different assumed pulse shapes,
    none of which is the 3 Hz kernel's own response, and C18i/C18j subtract a shape whose sidelobes (-0.555 at +-4
    samples) are where the 3 Hz response has none.
  Effect: the 3 Hz detector numbers of Y.32 (C18h: LOG6 3/16 on U8, 0 on N8; C18i: LOG6 3 and 2 of 16; C18j: uncapped
    3 and 1 of 16) are not comparable with each other (the C18h vs C18i difference is attributed to the +-2 s terms
    but also changes AC), and the C18i/C18j 3 Hz runs leave or create spurious residual energy after each atom, which
    affects atoms 2..6 of every window. The 2 Hz runs (including the C18j candidate that "meets the gate", 5/16 on U8)
    are NOT affected. Oracle maps (single-atom score maps, no deflation) are not affected.
  Measured (c18i_f3_acfix_bh.py -> c18i_f3_acfix_bh.txt): the C18i 3 Hz LOG6 run repeated with the only change that
    set_kernel precedes the import (C18h's AC). Events recalled of 16, stored vs re-run: N8 LOC+T 30/h 3 -> 2, 60/h
    3 -> 4, 10/h 0 -> 1, LOC 30/h 4 -> 3; U8 LOC+T 30/h 2 -> 2, 60/h 3 -> 4, LOC 60/h 5 -> 6. So the C18i/C18j 3 Hz
    readings move by +-1 event depending only on import order: of the size of the differences that Y.32 reads
    between configurations (e.g. 'with the 3 Hz filter, 3 and 2 with LOG6').
  Severity: exploratory numbers (C18h/C18i/C18j at 3 Hz); no registered result; the gate candidate (2 Hz) unaffected.

F2 [REG-number, decision probably unchanged] The "exact predicted sample" is the FLOOR of the predicted time, not the
    nearest sample, so exact-time readers lose on average 22 % of the arrival energy before any timing error.
  Where: certified_fw.py:168 (_idx_node: (tt / DT).astype(int)), used by task2c_methods.BlockDict.idx (BOMP+SC,
    MTSTACK+SC, GL-FW+SC of 2C), task2d_methods.node_vectors_v(peak=False) (MT-FW-EX+SC of 2D) and by every peak
    window; c10_lib.py:131-133 (Eng.IDX/frac), c11_lib.py:358 (clone_eng), c18j_layered.py:75.
  What: idx = int(t / DT) truncates, so the sample read by a method without peak search lies on average 0.5 sample
    (31 ms) and up to 1 sample (62.5 ms) EARLY of the continuous prediction; the +-4-sample peak window is likewise
    centred 0.5 sample early (covers [-4 - f, 4 - f] samples, f in [0, 1)).
  Reproduction (floor_bias_bh.py -> floor_bias_bh.txt): 2 Hz Ricker arrival through the 2 Hz matched filter, exact
    predicted time, f ~ U(0, 1): mean energy fraction read at the floor sample 0.783 (worst 0.419); at the nearest
    sample 0.938 (worst 0.820). The peak-search readers recover ~1.0.
  Effect: the handicap applies only to the comparators read at the exact predicted sample (2C: BOMP+SC, MTSTACK+SC,
    GL-FW+SC; 2D: MT-FW-EX+SC; the convex problem of 2C-b/E33), i.e. it inflates the measured value of the peak search
    (E35, rule 2C-a/2C-b, the "grid" attribution of E33) by an implementation detail rather than by timing error or
    grid discretisation. With the 3 km / 0.1 s grid the true-node timing error is already of order 0.1-0.3 s, so the
    decision of 2C-b (23 of 24) very probably stands, but the numerical gaps of 2C and the MT-FW-EX ablation of 2D are
    biased against exact-time reading. Not tested end to end (would require re-running 2C cells with rounding).
  Severity: changes registered numbers (2C, 2D ablation) in the direction that favours peak search; decisions unlikely
    to flip. All comparisons that give every method the same +-4 peak search (2D BOMP-PK vs MT-FW, 2F, 2I, 2M) are
    unaffected (the asymmetric window is common to all).

F3 [COSM] Calibration windows of R0 (and the C18 readings) assume the origin at 6.5 s of window time, but the window
    starts at the ROUNDED sample, so the true origin is 6.5 + delta, |delta| <= 1/32 s.
  Where: r0/r0_run.py:56-59 (ts = e["t"] - 6.5; R.window rounds ts to a sample, r0_lib.py:144), the origin passed is the
    constant 6.5; same in explore_contrib/c18a_timing.py:42-43 (readings tobs relative to 6.5).
  Reproduction: first CAL target t = 9.67 s: ts = 3.17 s, window starts at round(3.17 x 16) / 16 = 3.1875 s, so the
    catalogue origin sits at 6.4825 s of window time, not 6.5 (error -17.5 ms). Over the 16 CAL targets the error is
    uniform in [-31, +31] ms and common to all readings of an event.
  Effect: an event-common timing error of sd ~18 ms added to every catalogue reading used for +SC, S2, sigma_catalogue,
    the C18a/C18i timing ladders and the c18j layered terms. It is absorbed by event terms where they exist and is the
    same for every model compared; it adds noise, not bias, to the median station terms. Negligible next to the
    0.35-0.6 s timing errors measured. Fix: pass e["t"] - k * DT (k the rounded start sample) as the window origin.

F4 [EXPL / descriptive] The +SC corrections applied to PhaseNet picks are measured on matched-filter ENERGY PEAKS, while
    PhaseNet picks ONSETS; the corrected picks inherit a phase-dependent peak-minus-onset lag.
  Where: r0/r0_picks.py:137 (picks_sc = pick - corr_sc), corr_sc from station_corrections.estimate_station_corrections
    (energy peak of the 2 Hz matched filter relative to the catalogue prediction).
  What: corr = static + L_b, with L_b the lag of the MF-energy peak behind the onset for phase b. pick - corr =
    predicted arrival - L_b, so P and S picks are pulled early by different amounts and the corrected S-P times are
    biased by -(L_S - L_P). The verification's own numbers (r0_verification.txt 6.1 and 6.7b) show the size: with a
    +-2 s search the S terms are +1.74 to +1.91 s at SRT/CCC/TOW2 while the PhaseNet S-onset residuals at the same
    stations are +1.1 to +1.4 s, i.e. L_S ~ 0.4-0.6 s. With the frozen +-1 s search (D1) the S terms are instead
    truncated near +0.1-0.2 s.
  Effect: the +SC associator arms (GaMMA+SC, PyOcto+SC) are mis-specified independently of D1 (correcting the search
    width alone would over-correct S picks by ~0.5 s). BESTPICK takes the max over raw and +SC arms, so the registered
    R0 decision is unchanged; the descriptive +SC numbers and any future registered test that feeds peak-based terms to
    onset pickers (draft R1) are affected. Fix: estimate pick-arm terms from pick residuals (pick - catalogue
    prediction), not from MF peaks.

F5 [EXPL; bears on the registered R1 gate, which survives on U8 under the proper held-out estimate] In-sample station
    terms in every CAL development reading (C18d-C18j and the gate): the station terms are medians over the SAME 16
    catalogue events (M >= 2.0, CAL) that are then counted as detected.
  Where: r0/r0_run.py:53-62 (calwin = all CAL events with M >= 2.0 -> +SC, S2, sigma); explore_contrib/c18j_layered.py:
    47-67 (corrections over net.calwin) and 106-118 (detector scored on those events by c18d_analyze.py); same pattern in
    c18d_detect.py, c18i_widesc.py (detect), c18h_detect.py.
  What: each target event contributes its own peak delays to the per-station/phase median that sets the predicted times
    used to detect it (and its catalogue origin anchors the LOC+T origin). With 16 events, several station-phases have
    only a few gated readings, so one event can move a term by up to 0.8-1.2 s. The R0 registered EVAL is not affected
    (terms from CAL, evaluation on EVAL), and C18a used leave-one-event-out for the timing ladder, but the detector-level
    CAL readings and the gate ("at least 5 of the 16 CAL events ... on N8 or U8") do not; the R1 draft treats the gate as
    met. Only the "about twenty configurations" selection effect is declared, not this one.
  Reproduction (c18j_loeo_bh.py -> c18j_loeo_bh.txt): the stored C18j run is reproduced exactly (terms identical), then
    re-run with terms re-estimated per window without (NARROW) the calibration events that window can hit (origin in
    [ts + 4.5, ts + 8.5) s, the LOC+T reach of its owned range) or (WIDE) every event inside the 40 s window.
    Events recalled of 16, LOC+T at 30 false/h, in-sample / NARROW / WIDE:
      U8 MT-FW without cap (gate candidate) 5 / 5 / 1;  N8 4 / 2 / 3;  U8 LOG6 2 / 2 / 1;  N8 LOG6 1 / 0 / 0.
    LOC at 30/h: U8 NOCAP 5 / 5 / 1, N8 NOCAP 5 / 4 / 4, U8 LOG6 5 / 3 / 2.
  Effect: with the held-out estimate that removes exactly the leakage (NARROW), the gate candidate still reaches 5/16 on
    U8 (gate met at its threshold), but its N8 reading falls from 4 to 2 and the LOG6 readings fall by 0-2 events. The U8
    pass is fragile: removing also the other events present in the window (WIDE, a stricter but still legitimate
    out-of-sample estimate with fewer calibration events) drops it to 1/16. Y.32 / the gate log entry should report the
    held-out reading and this sensitivity; in-sample CAL readings are optimistic by up to 2 events of 16.
  Severity: changes exploratory numbers (C18 CAL readings); the registered gate decision is unchanged under the proper
    (NARROW) held-out estimate, but only at the threshold.
